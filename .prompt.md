# Custom Prompt Templates for prompt_hub

This file defines reusable prompt templates optimized for this repository.

## Using These Templates

These templates can be used by Copilot and other AI agents when working in this repository. They provide context and structure for common tasks.

---

## Template: Code Review for Rust Changes

```
You are reviewing a Rust pull request for the prompt_hub monorepo.

**Context:**
- Project: Multi-crate Rust workspace (prompt-hub lib, prompthub CLI, prompthub-server)
- MSRV: 1.91.1, Rust 2024 Edition
- Constraint: #![forbid(unsafe_code)]
- Database: libsql (SQLite-compatible)

**Review Checklist:**
1. Does the code compile with all features? `cargo check --all-features`
2. Do all tests pass? `cargo test --all-features`
3. Does clippy pass? `cargo clippy --all-targets --all-features`
4. Are there any unsafe blocks? (Should be zero)
5. Do types use models.rs definitions or create new ones unnecessarily?
6. Are error types from error.rs properly used?
7. Is the module in the correct dependency position (no circular deps)?
8. Are async operations properly awaited?
9. Are transactions used for multi-step database operations?
10. Are migrations numbered sequentially if schema changed?

**Required Documentation:**
- Public API has doc comments
- Complex logic has inline comments
- CHANGELOG.md updated if user-facing
- README.md/SPEC.md updated if feature-level change

Report any issues found and suggest fixes.
```

## Template: Implementing a New Feature

```
You are implementing a new feature for prompt_hub following this pattern:

**Step 1: Design (models.rs)**
Define all types needed by the feature:
- New struct/enum definitions
- Implementation methods with clear signatures
- Documentation with examples

**Step 2: Storage (storage.rs)**
Implement database layer:
- SQL schema additions (new migration file)
- Storage methods using libsql
- Comprehensive tests

**Step 3: Feature Module**
Create new module (e.g., myfeature.rs):
- Feature implementation
- Error handling with HubError
- Integration with other modules
- Full test coverage

**Step 4: Hub Integration (hub.rs)**
Add to the PromptHub coordinator:
- Create module instance
- Expose through public PromptHub methods
- Thread through to CLI/server

**Step 5: API Exposure**
Add HTTP routes (prompthub-server/src/routes.rs):
- Request/response types
- Handler function
- OpenAPI documentation

**Step 6: CLI Integration (prompthub/src/commands/)**
Add command handler:
- Argument parsing
- Call hub methods
- Display output to user

**Step 7: Documentation & Tests**
- Integration tests in tests/
- Example code in examples/
- Update SPEC.md if user-facing
- Update CHANGELOG.md

All steps must pass: cargo test --all-features && cargo clippy --all-targets --all-features
```

## Template: Debugging Compilation Errors

```
You are debugging a Rust compilation error in the prompt_hub monorepo.

**Systematic Approach:**

1. **Read the error message carefully** — Rust errors are specific
2. **Find the file and line**: Check prompt-hub/src/ or prompthub-server/src/
3. **Identify the error type**:
   - Type mismatch? Check models.rs for correct type
   - Missing import? Check that module is exported from lib.rs
   - Method not found? Verify the struct/enum definition
   - Borrow checker? Ensure proper ownership handling
   - Async issue? Check that .await is used correctly

4. **Search the codebase** for similar working code
5. **Check dependencies** with `cargo tree` for missing imports
6. **Verify MSRV compatibility** — Don't use features from Rust 1.92+
7. **Run cargo check** to test your fix without full compilation
8. **Test edge cases** — Add tests before moving on

**After fixing:**
- cargo check --all-features
- cargo test --lib <module>::
- cargo clippy --all-targets --all-features

**If stuck:**
- Check plan.md for known blockers
- Review SESSION.md for context on this error
- Look at git history: git log -p -S "error term"
```

## Template: Database Schema Changes

```
You are making a database schema change to the prompt_hub libsql database.

**Migration Process:**

1. **Create migration file**: migrations/000N_description.sql
   - Numbered sequentially (N increments)
   - Name is descriptive: 0010_add_user_roles.sql

2. **Write backward-compatible SQL**:
   - ADD COLUMN with DEFAULT (don't require existing data)
   - Add indexes AFTER tables
   - Use transactions for multiple statements
   - Never DROP columns without deprecation period

3. **Update models.rs**:
   - Add/modify struct fields
   - Update From<> implementations
   - Update tests

4. **Update storage.rs**:
   - Modify insert/update queries
   - Add new retrieval methods
   - Update tests to verify migration works

5. **Test the migration**:
   - Create fresh database
   - Run migrations in order
   - Verify old and new data work
   - Test rollback scenarios

**Example migration header:**
\`\`\`sql
-- Migration 0010: Add user roles
-- Creates roles table and updates agents table with role_id foreign key
-- Backward compatible: existing agents get DEFAULT role 'user'

BEGIN TRANSACTION;

CREATE TABLE roles (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL UNIQUE,
    capabilities TEXT NOT NULL -- JSON array
);

ALTER TABLE agents ADD COLUMN role_id INTEGER REFERENCES roles(id) DEFAULT 1;

INSERT INTO roles (name, capabilities) VALUES ('user', '["read"]');

COMMIT;
\`\`\`

**After migration:**
- cargo test --all-features
- Verify CHANGELOG.md updated
- Update SPEC.md if user-visible change
```

## Template: Performance Optimization

```
You are optimizing performance in the prompt_hub codebase.

**Before Optimizing:**
1. Measure the current performance: cargo bench
2. Profile with: cargo flamegraph --bench <name>
3. Identify the bottleneck (don't guess)

**Common Optimizations:**
- **Search**: Use FTS5 FAST mode for most queries, SMART for precision
- **Vectors**: Batch embedding generation, cache results
- **Locks**: Use TTL to prevent deadlocks
- **Database**: Use transactions, batch inserts, add indexes
- **Async**: Ensure no blocking operations in async code

**After Optimization:**
1. Benchmark again: cargo bench
2. Document performance improvement (link to commit)
3. Verify no regression in other benchmarks
4. Update CHANGELOG.md with performance note

**Never compromise correctness for speed.**
```

## Template: Security Review

```
You are performing a security review of prompt_hub code changes.

**Checklist:**

1. **No unsafe code** — Verify with grep "unsafe {" (should find zero)
2. **SQL injection prevention** — All queries parameterized, no string concat
3. **Hardcoded secrets** — grep for "password|secret|key|token" in code
4. **Authentication** — authorize_action called before sensitive operations
5. **Audit logging** — All mutations logged with audit_log()
6. **Error messages** — No sensitive info in error messages
7. **Input validation** — Sanitize user input (especially prompts)
8. **Rate limiting** — Rate limits applied to API endpoints
9. **Encryption** — Sensitive data encrypted at rest and in transit
10. **Access control** — RBAC properly enforced

**Privacy Checks:**
- PII detection active (privacy.rs)
- User data not logged unnecessarily
- Data deletion properly implemented
- GDPR compliance if applicable

**Dependency Security:**
- No suspicious dependencies added
- Check transitive dependencies with: cargo audit

**Report findings** with context and suggested fixes.
```

        assert_eq!(retrieved, "data");
    }

    // Async helper for test setup
    async fn create_test_hub() -> PromptHub {

        // Initialize with defaults
        // Return ready-to-test hub
    }
}
\`\`\`

**Test Rules:**
- One logical test per function
- Clear test names describing the scenario

## Quick Reference

### Common Grep Patterns
```bash
# Find all pub fn definitions
grep -r "pub fn " prompt-hub/src/

# Find all struct definitions
grep -r "pub struct " prompt-hub/src/

# Find all test functions
grep -r "#\[test\]" prompt-hub/src/

# Find all TODOs
grep -r "TODO\|FIXME" prompt-hub/src/

# Find all unwrap() calls (may hide errors)
grep -r "\.unwrap()" prompt-hub/src/
```
