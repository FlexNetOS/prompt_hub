# Agent Configuration for prompt_hub

## Purpose

This agent specializes in developing the prompt_hub Rust monorepo. It understands:
- Multi-crate Rust workspace structure
- libsql database operations and migrations
- Async/await patterns and error handling
- Full-text search (FTS5) and vector embeddings
- HTTP API design with OpenAPI
- CLI binary development

## Activation Rules

Activate this agent when:
- Working on `prompt-hub/`, `prompthub/`, or `prompthub-server/` crates
- Implementing new features from SPEC.md
- Fixing compilation errors or test failures
- Adding database migrations
- Designing HTTP endpoints

## Required Context

Before starting any task:
1. Read `.instructions.md` for project standards
2. Check `plan.md` for current development wave
3. Review `SESSION.md` for recent decisions
4. Verify the task doesn't conflict with existing work

## Workflow

### For New Features
1. Define types in `models.rs`
2. Add storage layer in `storage.rs`
3. Implement feature in a new module
4. Integrate into `hub.rs`
5. Add HTTP routes in `prompthub-server/src/routes.rs` (if applicable)
6. Write comprehensive tests
7. Update `SPEC.md` if user-facing

### For Bug Fixes
1. Check `plan.md` for known blockers
2. Identify the module(s) affected
3. Write a failing test first
4. Fix the code
5. Verify all tests pass
6. Commit with reference to the bug

### For Refactoring
1. Create a feature branch
2. Make changes incrementally
3. Run `cargo test --all-features` after each change
4. Update documentation if APIs changed
5. Merge with clear commit messages

## Constraints

- ✅ **Safe Rust only** — `#![forbid(unsafe_code)]` is non-negotiable
- ✅ **No hardcoded secrets** — Use config files and environment variables
- ✅ **Async throughout** — Never block in async code
- ✅ **MSRV 1.91.1** — Don't use features from newer Rust versions
- ✅ **Database safety** — Always use transactions for multi-step operations
- ✅ **No circular deps** — Verify with `cargo tree`
